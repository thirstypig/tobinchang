00

How this website actually works

Before you change anything, it helps to know what you're changing. The whole system is only three parts.

  • Your computer A folder called tobinchang. Ordinary files. This is your workbench — mess it up freely.
  • GitHub The copy that counts. It keeps every version you've ever saved, so nothing is ever really lost.
  • tobinchang.com What the world sees. GitHub rebuilds it automatically about a minute after you send changes.

You edit files in the folder on your computer. You push them to GitHub. GitHub puts them on the internet. That's it — that's the entire machine. Everything else in this manual is just detail.

The one rule worth memorising

A folder with a file called index.html inside it becomes a page on your site. The folder howto/ is why this page lives at tobinchang.com/howto. Make a folder called music/ with an index.html inside, and you have tobinchang.com/music.

01

Get a GitHub account

GitHub is where your website lives. It's free, and you only do this once.

  1. Go to github.com/signup.
  2. Choose your username carefully. It becomes part of web addresses, it's public, and changing it later breaks links. Pick something you'd be happy for a stranger — or a future employer — to read.
  3. Use an email you'll still have in five years.
  4. Turn on two-factor authentication when it offers. It's the difference between an account you own and an account you used to own.
Careful

Everything you push to GitHub is public by default, and search engines read it. Treat it like a poster on a wall, not a diary. Never put your home address, your phone number, your school schedule, or a password in a file.

02

Open the Terminal

The Terminal is a window where you type instructions to your computer instead of clicking them. It looks intimidating and isn't. You'll use maybe five commands total, and your AI helper will handle the rest.

  1. Press ⌘ + Space.
  2. Type Terminal.
  3. Press Return.

A window opens with a blinking cursor. When this manual shows a black box with an orange $, type what comes after it and press Return. Don't type the $ itself.

Try one now — this just asks the computer where you are:

pwd

You'll need one more thing installed, called Node. Check whether you already have it: 

node --version

If that prints a number like v22.19.0, you're set. If it says "command not found", go to nodejs.org, download the version marked LTS, and run the installer like any other app.

03

Install your AI helper

This is the part that makes the whole thing possible. Your helper reads your files, writes the code, and saves your work to GitHub — you describe what you want in plain English.

Pick one. They do the same job, and you can switch later.

  • Claude Code

    by Anthropic

    npm install -g @anthropic-ai/claude-code

    Then start it any time by typing claude.

  • Codex

    by OpenAI

    npm install -g @openai/codex

    Then start it any time by typing codex.

The first time you run it, it'll ask you to sign in through your browser. Follow the prompts. This also happens only once.

If the install fails

An error mentioning EACCES or "permission denied" means your computer is protecting a folder. Don't paste in a fix you found online. Copy the whole error message, and ask for help — that's what Station 10 is for.

04

Get the site onto your computer

Cloning means downloading your own copy of the website to work on. Run these one line at a time.

First, move to your Documents folder:

cd ~/Documents

Then download the site:

git clone https://github.com/thirstypig/tobinchang.git

Then step into the folder you just downloaded:

cd tobinchang

Now start your helper:

claude

You're in. Your helper can now see every file on your website, and you can start talking to it.

Every time after this

Opening the Terminal and typing cd ~/Documents/tobinchang then claude is the whole startup routine. Two lines, forever.

05

The everyday loop

Every change you'll ever make follows the same three beats. Learn this rhythm and you never have to memorise a command again.

  • 1 · AskTell your helper what you want, in normal words.
  • 2 · LookOpen the site on your computer and check it with your own eyes.
  • 3 · ShipAsk your helper to save and push it. A minute later it's live.

Looking before you ship

Never push something you haven't looked at. To see your site on your own computer, open a second Terminal window and run: 

cd ~/Documents/tobinchang && python3 -m http.server 3130

Then open localhost:3130 in your browser. That's your site, running privately on your machine. Refresh the page after each change. Press Ctrl + C in that window to stop it.

Shipping it

You don't need to learn Git commands. Just ask, in the same window where your helper is running:

  • Ship it

    Commit these changes with a clear message and push them to GitHub.

Wait about a minute, then load tobinchang.com in your browser. Your change is on the internet.

06

Make your first change

Let's do the smallest possible real edit, start to finish, so you've done the whole loop once.

  1. Open the Terminal and run cd ~/Documents/tobinchang, then claude.
  2. Paste the prompt below and press Return.
  3. Read what it says it's going to do. If it looks right, let it go ahead.
  4. Check it at localhost:3130.
  5. Ask it to commit and push.
  • Your first edit

    Open the home page and change the headline to say "Hi, I'm Tobin." Keep the existing fonts and colours exactly as they are. Show me the change before you save it.

That's the entire job. Everything else you'll ever do here is a bigger version of those five steps.

07

Make a whole new page

Remember the rule from Station 00: a folder with an index.html inside it becomes a page.

So the structure of your site looks like this:

tobinchang/
├── index.html          → tobinchang.com
├── howto/
│   └── index.html      → tobinchang.com/howto
├── music/
│   └── index.html      → tobinchang.com/music
└── assets/
    └── manual.css      → the styling

You don't have to make those folders by hand. Describe the page you want and let your helper build it:

  • New page

    Make a new page at /music where I can write about songs I like. Use the same fonts, colours and styling as the rest of the site so it matches. Put three example entries on it so I can see how it looks, and add a link to it from the home page.

  • New page — projects

    Make a new page at /projects that lists things I've built. Each one should have a title, a short description, and a photo. Match the style of the rest of the site, and use grey boxes where the photos will go until I have real ones.

Why this matters

Notice both prompts say "match the style of the rest of the site." Without that, you'll get a page that works but looks like it belongs to somebody else. Say it every time.

08

Write a prompt that works

A prompt is just an instruction. Weak prompts get weak results — not because the helper is dumb, but because you left it guessing.

The four ingredients

  • What — the thing you want changed.
  • Where — which page or which part of the page.
  • How it should feel — calm, loud, funny, serious, simple.
  • What not to touch — the stuff you already like.

Weak, then strong

  • Weak — too vague to act on

    make the site better

  • Strong — leaves nothing to guess

    On the home page, the text under my name is hard to read on a phone. Make it bigger and add more space between the lines. Don't change the colours or the headline.

Three habits worth having

  • Ask for one thing at a time. Five changes in one prompt means five chances for something to go sideways at once.
  • Say "show me first" when you're unsure. You can always approve after you've read it.
  • If the result is wrong, say what's wrong — don't start over. "Almost, but the spacing is too tight" gets you there faster than rewriting the prompt from scratch.
09

The prompt pack

Copy these straight into your helper. Change the words in them to suit what you actually want — they're starting points, not spells.

Everyday edits

  • Change some words

    On the home page, change the sentence about what I do so it says I'm learning guitar and I play basketball. Keep the same tone and don't change anything else.

  • Add a photo

    I put a photo called me.jpg in the assets folder. Add it to the home page under the headline, make it round, and keep it a reasonable size on phones.

  • Add a link

    Add a link at the bottom of every page that goes back to the home page. Make it small and quiet, not a big button.

Making it look better

  • Fix it on phones

    Check every page on a phone-sized screen and fix anything that overflows, overlaps, or is too small to read. Don't redesign anything — just make what's there work properly.

  • Try a new look

    Show me three different colour schemes for the site. Keep the layout and fonts the same, only change the colours. Describe each one before you build it so I can pick.

  • Slow down

    The home page feels cramped. Add more space between the sections so it feels calmer, without making the text smaller.

Understanding your own site

  • Get your bearings

    Give me a tour of this website. What files are here, what does each one do, and which one should I edit if I want to change the home page?

  • Explain it to me

    Explain what you just changed and why, like I'm new to this. Point out the part I'd need to edit if I wanted to tweak it myself later.

  • What changed?

    What have I changed since the last time I pushed to GitHub? List it in plain English, not code.

Shipping and safety

  • Ship it

    Commit these changes with a clear message and push them to GitHub.

  • Check before shipping

    Before I push this — check every page for broken links, missing images, and typos. Tell me what you find and don't fix anything yet.

  • Privacy sweep

    Look through the whole site for anything personal I shouldn't be publishing — my address, phone number, school name, email, or anything a stranger could use to find me. List anything you find.

10

When something breaks

It will break. That's normal, and it's not a sign you're doing it wrong — it's the actual job.

The thing worth knowing: nothing you do here is permanent. GitHub keeps every version you've ever saved. Any mistake can be walked back.

  • Undo everything since the last save

    Undo all the changes I've made since my last commit and put the files back how they were. Tell me exactly what you're about to throw away first.

  • Go back one step

    My last change broke the site. Show me what the previous version looked like and put it back.

  • Decode an error

    I got this error and I don't understand it. Explain what it means in plain English, then tell me how to fix it: [paste the whole error here]

  • The site didn't update

    I pushed my changes but tobinchang.com still shows the old version. Check whether the push actually worked and whether the deploy succeeded, and tell me what went wrong.

When you're properly stuck

Copy the entire error — every line, not just the part that looks important — and paste it in. Half an error message is a guessing game. If it's still stuck after a couple of tries, stop and ask Uncle James. Nobody gets points for wrestling it alone.

11

Rules of the road

Short list. Worth taking seriously.

  • The internet is permanent. Once something is published, assume a copy exists somewhere forever — even after you delete it. Post accordingly.
  • No personal details. Your address, phone number, school, birthday, and daily schedule don't belong on a public page. A first name and a general area is plenty.
  • Never paste a password or a key. Not into a file, not into a chat with your helper, not anywhere. If something asks you to, that's your signal to stop and ask.
  • Read before you say yes. Your helper will ask permission before it does anything real. Actually read what it's proposing — that pause is your safety net, and skipping it is the one habit that gets people into trouble.
  • Other people's photos need permission. Friends, family, anyone. Ask first. Same for music, art, and writing that isn't yours.
  • If something feels off, stop. A weird pop-up, an unexpected request to sign in, an email about your account you weren't expecting. Close it and ask. Being wrong costs nothing; being right matters a lot.

Glossary

Words people will use around you. None of them are as complicated as they sound.

repo
Short for repository. The folder that holds your whole website, including its history.
clone
Download your own working copy of the repo onto your computer.
commit
Save a snapshot of your changes, with a note about what you did. Like a checkpoint in a game.
push
Send your commits up to GitHub. This is the step that puts things on the internet.
pull
Bring down changes someone else made, so your copy is current.
branch
A side copy where you can try something risky without touching the real site.
deploy
The automatic process that turns your files into the live website after you push.
localhost
Your own computer, pretending to be a web server, so you can preview privately.
terminal
The window where you type commands instead of clicking buttons.
prompt
What you type to your AI helper. An instruction in plain English.
HTML
The file format that holds a page's words and structure.
CSS
The file that decides how it all looks — colours, fonts, spacing.
